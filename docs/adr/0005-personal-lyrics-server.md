# ADR-0005: 개인 가사 서버는 "소스"가 아니라 "캐시 계층"으로 둔다

- 상태: 채택 (2026-07-28)
- 관련: ADR-0002(플러그형 소스·번역), ADR-0003(멀티플랫폼 저장소·거버넌스), ADR-0004(텔레메트리)

## 배경

기기마다 `translations.db`(가사·번역 캐시)가 따로 놀아, 같은 곡을 PC에서 듣고 폰에서 다시 들으면
제공자 검색과 유료 번역을 처음부터 반복한다. 캐시 파일을 클라우드 폴더로 주고받는 방안은 SQLite
잠금·부분 동기화 손상 때문에 보류돼 있었다.

개인 서버 한 대(테일넷 안의 Oracle 무료 인스턴스)를 교환소로 두면 이 문제가 통째로 사라진다.

## 결정

1. **가사 서버는 `LyricsSourceRegistry`의 "소스"가 아니라 코디네이터의 캐시 계층으로 넣는다.**
   ADR-0002는 "새 소스는 레지스트리 한 줄"을 규정했지만, 그 길을 **의도적으로 가지 않는다** —
   `LyricsSearchService`는 모든 제공자를 우선순위 없이 병렬 호출하고 품질로 승자를 뽑으므로,
   서버를 소스로 등록하면 **서버가 히트해도 외부 제공자를 매번 두드리게 된다**. 외부 트래픽·지연을
   줄이는 것이 이 기능의 목적이므로 소스 등록은 목적을 달성하지 못한다. 또한 `ILyricsProvider`는
   읽기 전용이라 업로드 경로가 없다.
   대신 `LyricsCoordinator.RemoteCache`(`IRemoteLyricsCache`)를 두어
   **로컬 캐시 → 서버 → 제공자 검색** 3단 계단을 만든다.

2. **인터페이스는 비동기, 실패는 조용한 강등.** 로컬 캐시의 `Get`은 동기이고 트랙 변경 경로의
   첫 `await` 이전(=UI 스레드)에서 실행되므로, 여기에 동기 HTTP를 넣으면 곡이 바뀔 때마다 UI가
   멈춘다. 원격 조회는 `Task`를 돌려주고 실패·타임아웃·미접속은 **예외 대신 null**로 강등한다.
   서버가 없거나 테일넷 밖이어도 앱 동작은 이전과 동일하다(순수 가산 계층).

3. **서버는 C#(`src/Musebase.Server`, ASP.NET Core)으로 만들고 `Musebase.Core`를 재사용한다.**
   Cloudflare Worker(ADR-0004의 텔레메트리 패턴)는 운영이 더 편하지만, 키 정규화와 LRC 파싱을
   JS로 재구현해야 해 클라이언트와 어긋날 위험이 크고, 제공자들이 EAPI 암호화·KRC/QRC 복호에
   의존해 서버가 직접 검색·번역하는 다음 단계(일괄 사전 채우기)를 아예 막는다.
   키는 `LyricsCacheStore.MakeKey`를 **같은 코드로** 호출하므로 정의상 어긋나지 않는다.

4. **노출은 Tailscale, 공개 포트는 열지 않는다.** 앱은 루프백만 리슨하고 `tailscale serve`가
   HTTPS 종단을 제공한다. 이는 보안뿐 아니라 실용적 이유도 있다 — Android는 평문 HTTP를 기본
   차단하므로, 정규 인증서가 붙은 `*.ts.net` 주소면 매니페스트를 손대지 않고 붙는다.

5. **저장은 무손실.** 서버는 LRC 문자열을 파싱·재직렬화하지 않고 그대로 보관한다. 클라이언트
   캐시(`LyricsCacheStore`)를 서버 저장소로 재사용하면 요청마다 파싱→재직렬화 왕복이 생겨
   원본이 미세하게 변형될 수 있다. 코어는 키 계산·읽기 전용 판정에만 쓴다.

6. **병합 정책으로 퇴화를 막는다**(계약 문서에 규정): 사용자 편집본은 자동 검색이 덮어쓰지 못하고,
   글자 단위 카라오케·번역이 붙은 가사는 빈약한 가사로 대체되지 않는다. 그 외에는 나중 것 우선 —
   번역이 점진적으로 채워지는 구조라 "먼저 것 유지"는 누적을 막는다. 삭제 API는 두지 않는다.

## 결과

- 새 최상위 컴포넌트 `src/Musebase.Server/`가 생긴다. 소유는 **core 에이전트**(코어를 직접 참조하고
  계약 문서와 함께 갱신되어야 하므로 — `backend/telemetry`와 같은 논리). CLAUDE.md 소유권 지도에 반영.
- 배포는 릴리스 태그 대상이 아니다(개인 인프라). 수동 `dotnet publish` + `scp` + systemd —
  ADR-0003이 규정한 플랫폼 릴리스 스킴과 별개이며 절차는 `src/Musebase.Server/deploy/README.md`에 둔다.
- API 계약은 `contracts/lyrics-api.md`(v1)가 단일 진실. 케이싱은 camelCase로,
  `contracts/playback-view-state.md`(PascalCase)와 다르다는 점을 문서에 명시했다.
- **개인정보**: 가사 전문과 번역이 서버에 축적되며, 이는 테일넷 내부에만 존재한다. 공개 배포 빌드의
  기본값은 **서버 미설정(=꺼짐)** 이라 사용자가 주소를 넣지 않는 한 아무 데이터도 나가지 않는다
  (ADR-0004의 "기본 꺼짐" 원칙과 일관). 토큰은 Windows에서 DPAPI로 암호화 저장하고, Android는
  앱 private 저장(암호화 아님)이라는 기존 한계를 그대로 따른다.

## 보완 (2026-07-29) — 관리자 UI

v1 배포 후 두 가지가 부족했다: ① 서버가 실제로 쓰이는지 확인할 방법이 없었고(조회 히트/미스를
아무 데도 기록하지 않았다), ② 틀린 가사가 한 번 박히면 모든 기기가 그것을 받는데 고칠 수단이 없었다.

- **조회 기록**은 `lookups` 테이블에 요청 단위로 남긴다(곡·결과·기기·시각, 기본 90일 후 자동 삭제,
  `MUSEBASE_LOG_LOOKUPS=0`으로 끔). 곡별 누적 카운터가 아니라 요청 단위인 이유는 **미스**(서버에 없는 곡)를
  기록해야 "채울 후보"가 나오기 때문이다. 청취 이력이 남는다는 점은 `deploy/README.md`에 고지한다.
- 결정 6의 **"삭제 API는 두지 않는다"는 기계 API(`/v1/*`)에 대한 것으로 유지**하고, 사람이 화면에서
  확인하고 지우는 경로만 관리자 UI에 둔다. 한 기기의 자동 판정이 전원의 캐시를 지우는 일은 여전히 없다.
  관리자 편집은 `origin=user`로 저장되어 병합 정책이 자동 검색으로부터 보호한다.
- `/admin/*`은 **계약 밖**이다(`contracts/lyrics-api.md`에 명시). 브라우저가 `Authorization` 헤더를 붙일 수
  없어 인증도 다르다 — 원 토큰 대신 만료·HMAC만 담은 서명 쿠키를 굽는다.
- 스키마 변경에 대비해 `PRAGMA user_version` 기반 마이그레이션을 이때 도입했다(`ALTER TABLE`은
  재실행하면 실패하므로 필요해진 뒤에 도입하면 늦다).

## 보완 (2026-07-31) — 번역 공유의 두 구멍

이 ADR의 목표 중 하나인 "한 기기가 번역하면 다른 기기는 다시 번역하지 않는다"가 **새로 검색한
곡에만** 성립하고 있었다. 원인은 설계가 아니라 두 곳의 비대칭이다.

- **업로드 시점이 검색 직후뿐이었다.** 가사 저장 당시 번역이 없으면(API 꺼짐·한도 초과·대상 언어
  불일치) 그 뒤에 채워진 번역은 어디에도 올라가지 않아, 서버 저장본이 영원히 번역 없이 남고
  기기마다 같은 곡을 각자 번역했다. 이제 **캐시·서버 히트 뒤 보충 번역이 실제로 채워진 경우에도**
  올린다. "실제로 채워진 경우"라는 조건이 핵심이다 — 무조건 올리면 같은 곡을 틀 때마다
  `revision`만 늘어난다. 클라이언트의 PUT 시점을 계약 문서에 명문화했다.
- **조회는 느슨한 키를 보는데 저장은 정확 키만 봤다.** 같은 곡이 기기별 표기로 갈려 두 행이 되고
  번역이 흩어진다(결정 4가 조회에만 적용되고 있었던 셈). 이제 `Upsert`도 `Get`과 같은 해석기를
  쓴다. 다만 합칠 때 `key`·제목·아티스트는 **먼저 저장된 표기를 유지**한다 — 이걸 요청 표기로
  바꾸면 원래 올린 기기의 정확 키 조회가 깨진다. 재업로드가 잦아지는 이번 변경과 짝이다.

## 후속

- v2: 서버가 번역까지 대행(`POST /v1/translate` + `MusebaseServerTranslator : ITranslator`).
  ADR-0002의 번역기 확장 지점을 정석대로 쓰는 것이며, 덤으로 기기가 유료 API 키를 갖지 않아도 된다.
- v3: 서버가 직접 검색·번역해 자주 듣는 곡을 미리 채우는 CLI(레이트 리밋·예산 상한 필수).
